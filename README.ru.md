# CD

**Независимое ревью кода и ограниченный цикл исправлений для Codex и Claude Code.**

[English](README.md) · [Инструкции скилла](skills/loop-code-review/SKILL.md) · [Лицензия MIT](LICENSE)

CD проверяет работу, реализованную в текущем чате, разбивает её на подзадачи и передаёт каждую независимому ревьюеру. Если обнаружены дефекты, новый агент вносит точечные исправления, а другой новый ревьюер проверяет результат.

Цель — **9,5/10 для каждой подзадачи**, максимум **пять циклов исправлений на весь запуск**. Для принятия результата также нужны успешные проверки, актуальный снимок файлов и отсутствие незакрытых существенных дефектов. Оценка выражает суждение ревьюера, а не гарантирует отсутствие ошибок.

Скилл называется `loop-code-review` и работает в двух средах. В начале запуска он определяет, где выполняется — в Codex или в Claude Code, — и дальше идёт по ветке этой среды. Протокол ревью, оценки, критерии приёмки, бюджет циклов и контрольные точки у обеих веток общие.

## Установка в Codex

Отправьте в Codex:

```text
$skill-installer Установи скилл из https://github.com/GeorgVahi/CD/tree/main/skills/loop-code-review
```

Устанавливать нужно папку `skills/loop-code-review` целиком, включая инструкции, справочные материалы, схему отчёта и CLI-помощник. Корень репозитория не является папкой скилла. Если после установки скилл не появился, перезапустите Codex. Установку из сторонних репозиториев поддерживает встроенный установщик: [официальная документация](https://learn.chatgpt.com/docs/build-skills#install-curated-skills-for-local-use).

Для установки фиксированной версии замените `main` в ссылке на опубликованный тег или SHA коммита.

### Ручная установка

Клонируйте репозиторий и скопируйте `skills/loop-code-review` в личный каталог скиллов. Команды используют [документированный путь локальных скиллов](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) и останавливаются, если скилл уже есть в этом каталоге.

**macOS / Linux (Bash):**

```bash
(
  set -eu
  git clone https://github.com/GeorgVahi/CD.git
  destination="$HOME/.agents/skills/loop-code-review"
  if [ -e "$destination" ] || [ -L "$destination" ]; then
    echo "loop-code-review already exists at $destination; preserve local edits before updating." >&2
    exit 1
  fi
  mkdir -p "$HOME/.agents/skills"
  cp -R CD/skills/loop-code-review "$destination"
)
```

**Windows (PowerShell):**

```powershell
git clone https://github.com/GeorgVahi/CD.git
if ($LASTEXITCODE -ne 0) { throw 'Clone failed.' }
$skillParent = Join-Path $HOME '.agents/skills'
$destination = Join-Path $skillParent 'loop-code-review'
if (Test-Path -LiteralPath $destination) {
    throw "loop-code-review already exists at $destination; preserve local edits before updating."
}
New-Item -ItemType Directory -Path $skillParent -Force | Out-Null
Copy-Item -LiteralPath './CD/skills/loop-code-review' -Destination $destination -Recurse
```

Для установки в общий проект скопируйте папку в `<project>/.agents/skills/loop-code-review`. Существующая установка Codex или встроенный установщик могут использовать `$CODEX_HOME/skills` (обычно `~/.codex/skills`); сохраняйте путь, которым управляет ваша установка. Не устанавливайте несколько копий скилла в каталогах обнаружения скиллов.

### Переход со старого имени `cd`

Прежние версии устанавливались как `cd` и вызывались через `$cd`. Сохраните локальные правки, удалите только старую установленную папку `cd` и установите `loop-code-review`, как описано выше. Контрольные точки в `.local/code-review/runs/` остаются совместимыми.

## Использование

Запустите CD в чате, где выполнялась реализация. В Codex:

```text
$loop-code-review
```

В Claude Code:

```text
/loop-code-review
```

При необходимости ограничьте область (в примерах используется `$` из Codex; в Claude Code вместо него наберите `/`):

```text
$loop-code-review Проверь и исправь только изменения авторизации, реализованные в этом чате.
```

Для ревью без правок:

```text
$loop-code-review Только ревью. Не изменяй файлы, не делай commit и push.
```

CD запускается **только явно**. В Codex автоматическое подключение отключено в метаданных, а установка не регистрирует slash-команду. В Claude Code за это отвечает `disable-model-invocation: true`, а имя скилла не перекрывает встроенные команды `/cd` и `/code-review`.

## Прогресс во время долгой работы

Пока CD работает, координатор отправляет общую сводку в тот же чат **каждые два часа**, начиная через два часа после запуска. В ней указаны завершённые и оставшиеся подзадачи, текущая работа, цикл исправлений, изменения с предыдущей сводки, блокеры и примерный диапазон оставшегося времени, если его можно обосновать фактическим темпом. Если общее число задач или время пока неизвестны, CD прямо сообщает об этом.

В режиме исправлений завершёнными считаются только задачи, которые сейчас проходят все критерии приёмки. В режиме только ревью отдельно указаны завершённые проверки и принятые результаты. Сводка приходит и при отсутствии завершённых задач; короткие сообщения о текущей работе не откладывают двухчасовой отчёт.

Срок следующей сводки сохраняется вместе с состоянием запуска и не сбрасывается при сокращении контекста или смене исполнителя. При возобновлении после пропущенного срока CD отправляет одну актуальную сводку и отсчитывает следующий интервал от неё. Завершение и блокеры, останавливающие работу, сообщаются сразу. При завершении или паузе отчёты прекращаются; сам скилл не может разбудить неактивный чат. Подробности — в [правилах отчётности](skills/loop-code-review/references/progress-reporting.md).

## Как проходит работа

1. Координатор по фактическим инструментам определяет среду (Codex или Claude Code) и идёт по её ветке.
2. Он определяет изменения текущего чата, включая уже закоммиченные, и фиксирует состояние репозитория.
3. Один агент без права редактирования выделяет подзадачи, критерии приёмки и базу сравнения.
4. Каждую подзадачу проверяет новый независимый ревьюер. Он не получает прошлые оценки и вердикты.
5. Для незакрытых подзадач выполняются точечные исправления и новое независимое ревью. Пять циклов — общий бюджет всего запуска.
6. Координатор сообщает оценки, исправления, фактические проверки, блокеры и результат публикации. Работа завершается после принятия всех подзадач или когда разрешённых выполнимых действий больше нет.

В режиме без правок CD останавливается после первичного ревью. Если в чате нет реализованной работы, он сообщает об этом, не превращая запуск в аудит всего репозитория.

| Критерий | Максимум |
| --- | ---: |
| Корректность и выполнение требований | 4,0 |
| Устойчивость и безопасность | 2,0 |
| Интеграция и риск регрессий | 2,0 |
| Сопровождаемость | 1,0 |
| Проверка результата | 1,0 |

[Контракт ревью](skills/loop-code-review/references/review-contract.md) задаёт ограничения оценки по серьёзности дефектов и необходимые доказательства. Незакрытые P0–P2, недоступная обязательная проверка, устаревший снимок файлов или существенная неопределённость не позволяют принять результат даже при достаточной числовой оценке.

## Требования и ограничения

- **Codex:** среда с доступом к рабочим файлам и возможностью создавать субагентов с новым контекстом либо запускать совместимый установленный Codex CLI. Для резервного запуска через CLI: авторизованный Codex CLI и поддержка `codex exec` с `--json`, `--ephemeral`, `--sandbox`, `--output-schema`, `--output-last-message` и передачей задания через stdin.
- **Claude Code:** инструмент `Agent` для субагентов с новым контекстом. Для необязательного резервного запуска через CLI: авторизованный `claude` CLI с `-p`, `--output-format stream-json`, `--no-session-persistence`, `--session-id`, `--permission-mode`, `--permission-prompts`, `--json-schema`, `--tools` и `--disallowedTools`. Подходит и CLI, встроенный в десктоп-приложение, даже если его нет в PATH, но вход приложения он не наследует: один раз выполните `claude auth login` этим бинарником сами.
- **Python 3.9+** для CLI-помощника. Он использует только стандартную библиотеку.
- Git для проверки Git-репозиториев и инструменты валидации самого проверяемого проекта.
- Уже существующий игнорируемый каталог внутри Git-проекта для контрольных точек. CD не меняет `.gitignore` проекта только ради запуска ревью.

CD использует встроенных субагентов, если их жизненный цикл позволяет создавать новые контексты. В Codex, если завершённые агенты продолжают занимать слоты и их нельзя закрыть, он переходит к отдельным новым CLI-заданиям — см. [runtime-recovery.md](skills/loop-code-review/references/runtime-recovery.md). В Claude Code завершённые субагенты освобождают слоты, поэтому CLI нужен только если инструмент `Agent` недоступен или лимит параллельных агентов исчерпан повторно — см. [ветку Claude Code](skills/loop-code-review/references/claude-code.md).

Вызов CD разрешает локальные исправления в пределах задачи, правил проекта и действующих полномочий. Скилл сохраняет чужие изменения, по умолчанию допускает одного пишущего агента и сохраняет счётчик циклов при восстановлении. Он не даёт новых разрешений на commit/push, не меняет выбранную модель, не устанавливает и не обновляет инструменты, не обходит лимиты аккаунта. В режиме только ревью нет staging, commit и push.

Задания агентов расходуют обычные лимиты Codex или Claude. Пять циклов — предел работы: запуск может завершиться ниже целевой оценки с честным отчётом об оставшихся дефектах или блокерах. Пакет документирован для Codex и Claude Code; другим агентным средам нужны эквивалентные механизмы исполнения и разрешений.

## Обновление и удаление

Установленная копия автоматически не обновляется при изменениях на GitHub. Сохраните локальные правки, обновите отдельный клон через `git pull --ff-only` и замените только установленную папку `loop-code-review` новой версией `skills/loop-code-review`. Встроенный установщик Codex отказывается перезаписывать существующий каталог и не является механизмом обновления.

Для удаления уберите только установленную папку `loop-code-review`. Сохраняйте родительский каталог скиллов и конфигурацию Codex или Claude Code.

```text
├── tests/test_run_agent_claude.py   Регрессионные тесты исполнителя Claude

```

Из корня репозитория (в Windows используйте `python` вместо `python3`):

```bash
python3 -B -m unittest discover -s skills/loop-code-review/tests -v
python3 -B skills/loop-code-review/scripts/run_agent.py --help
```

Тесты используют подставные CLI-процессы для обеих сред, не требуют авторизации и не расходуют лимиты модели. Они проверяют жизненный цикл заданий, снимки файлов, восстановление, лимит циклов, завершение процессов и метаданные скилла. Они не доказывают совместимость со всеми действующими моделями и средами Codex и Claude Code. Инструкция для участников и проверки перед выпуском находятся в [CONTRIBUTING.md](CONTRIBUTING.md).
